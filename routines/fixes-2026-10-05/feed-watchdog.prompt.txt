## What to do

Read the Command Deck artifact's database: artifact `1624daae-d683-405a-971d-c5828dce0f8d`, collection `state`. Use the ArtifactData tool.

Check each of these documents and work out how stale it is, from its own internal stamp (`syncedAt`, `checkedAt`, `updatedAt` or `meta.last_received` — whichever that document actually carries; say which you used):

`weatherSnapshot` · `newsSnapshot` · `marketSnapshot` · `aiNews` · `ratesSnapshot` · `calendarSnapshot` · `appleHealth` · `stravaSnapshot` · `strategySnapshot` · `liveFeeds` · `loftyLeads` · `zohoSync` · `leadResponse` · `leadTriage` · `runnerStatus` · `routineHealth` · `backupStatus` · `toolkitSnapshot` · `secondBrain` · `knowledgeFabric` · `knowledgeGraph` · `healthNotionSync` · `isaLadder` · `twinBrief` · `vanessaBrief`

For each, classify: `fresh` (within its expected cadence), `late` (past it but under 3 days), `stale` (3 or more days), `missing` (no document), `waiting` (the document exists, says in its own `status` that it is waiting on a person, and has never carried a stamp), or `unknown` (no usable stamp — say so rather than guessing). A document that does not exist is `missing`, never `fresh`.

Five documents need a rule of their own, because their stamp is not a plain field:
- `liveFeeds` is a bag of entries that the cloud writers update one at a time; they never touch its top-level `updatedAt`. Judge it by the newest `v.feeds.<key>.checkedAt` (set `stampField` to `feeds.*.checkedAt (newest)`) and name the oldest entry and its age in the row's `note`.
- `aiNews` carries no stamp field, only a prose `asOf`. The AI-news card is repainted from `liveFeeds.feeds.aiNewsList`, so use that entry's `checkedAt` (the stamp the deck's own freshness board uses) and set `stampField` to `liveFeeds.feeds.aiNewsList.checkedAt`.
- `marketSnapshot` carries no stamp field either, only a prose `asOf` such as "Oct 2, 2026 close ... Research run 2026-10-04". Take the session date that text names as a date-only stamp (00:00 UTC) and set `stampField` to `v.asOf (date in text)`. It is an end-of-session snapshot, so judge it by sessions, not hours: `fresh` while it holds the most recent completed U.S. session (Monday to Friday, after 21:00 UTC, ignoring weekends and exchange holidays), `late` one session behind, `stale` two or more behind. If the text names no date it is `unknown`.
- `healthNotionSync` is `waiting` while its `status` is `awaiting-first-phone-run` or its `lastSyncAt` is null: state `waiting`; `stampField`, `stamp` and `ageHours` null; the row's `note` is "waiting on Steven's first phone run". Once `lastSyncAt` has a value, judge it by that stamp like the rest.
- `isaLadder` is written only Tuesday to Saturday (about 14:30 UTC). Do not call it `late` merely because it is over 36 hours old on a Sunday or Monday: if no scheduled run has been due since its stamp it is `fresh`; otherwise the usual rule applies.
`openrouterFeeds` is retired (no page reads it, and its writer is paused): do not check it and do not report it.

Note anything whose stamp is **in the future** — that is a bug, not freshness, and it has already been found once on this account.

## What to write

One document, `feedFreshness`, in that same collection. **Every document in this store is `{v: <value>}` — no exceptions.** Send `data: {v: {...}}`, never the bare value; a top level that is not a single `v` key is a writer bug.

```
{v: {
  checkedAt: "<ISO 8601 UTC, the real clock at the moment you write>",
  by: "feed-freshness-watchdog (cloud)",
  counts: { fresh: <n>, late: <n>, stale: <n>, missing: <n>, unknown: <n>, waiting: <n> },
  worst: "<the single most overdue doc name (never a `waiting` one), or null>",
  futureStamps: [ "<doc names whose stamp is ahead of now>" ],
  docs: [ { doc: "<name>", state: "fresh|late|stale|missing|unknown|waiting",
            stampField: "<which field you read, or null>",
            stamp: "<its value, or null>", ageHours: <number|null>,
            note: "<optional: only where a rule above asks for one>" } ],
  note: "<one plain sentence: what changed since the last run, or that nothing did>"
} }
```

Read the existing `feedFreshness` first if it exists, and set `note` by comparing — a watchdog whose output never changes teaches nobody anything.

Then append ONE row to the `ciLog` document. Its rows are **exactly** `{date: "YYYY-MM-DD", text: "..."}` and no other shape — any other shape renders as "Invalid Date undefined" on the dashboard, which has already happened once. Read `ciLog` first, append to its existing array, keep the newest 200 rows, and write it back wrapped in `{v: ...}`. The text should name the counts and the worst offender in one sentence.
